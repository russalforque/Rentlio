# Password recovery

Forgot-password and new-password screens share the login layout, including light/dark themes and touch-sized controls. Reset requests trim email addresses before validation. The confirmation screen supports changing the address and resending after 60 seconds; Supabase remains responsible for enforcing server rate limits.

## Reset links from the Supabase dashboard

Dashboard-generated recovery emails can return to the configured Site URL, rather than the `/auth/confirm` redirect requested by the app. Previously, links landing on `/` or `/login` reached normal authentication redirects without running the email callback.

The app now detects email tokens before initializing the router, sends them through `/auth/confirm`, and opens `/set-password?mode=recovery` after a session is established. Default implicit-session links and custom `token_hash` templates both work. Expired links display an error with a way to request a fresh link. Invitation links still open account activation.

Deploy the updated app to apply this fix to hosted reset emails. In Supabase **Authentication > URL Configuration**, Site URL must point to the deployed app, and its `/auth/confirm` URL must be allowed for app-requested resets. Hosted settings and email templates were not changed by this local implementation.

Reference: [Supabase password recovery](https://supabase.com/docs/guides/auth/passwords) and [redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls).

## Verify locally

Run `npm run build`, `npm run lint` and `npm run test:unit`.

Start a separate Vite instance with synthetic configuration:

```powershell
$env:VITE_SUPABASE_URL='http://127.0.0.1:54321'
$env:VITE_SUPABASE_PUBLISHABLE_KEY='sb_publishable_synthetic_ui_qa'
npm.cmd run dev -- --host 127.0.0.1 --port 5186 --strictPort
```

Then run the browser suite with an existing Playwright installation and matching browser:

```powershell
$env:PLAYWRIGHT_MODULE='C:\path\to\playwright\index.mjs'
$env:QA_BROWSER_PATH='C:\Program Files\Google\Chrome\Application\chrome.exe'
node tests/ui/auth-recovery.mjs
```

Omit those variables when Playwright and its browser are installed locally. All external requests are mocked or blocked; no real emails are sent or passwords changed. Screenshots and results go to ignored `artifacts/auth-qa/`.

Coverage includes email validation, loading controls, resend cooldown and failures, keyboard focus, mobile layouts from 320px, dark mode, recovery links landing on the root/login/callback, custom token hashes, session persistence after reload, updating the password, and expired or incomplete links. Actual email delivery and the hosted Supabase URL configuration require a separate deployment check.

## Console messages

For default email links through `/auth/v1/verify`, an `otp_expired` error in the redirect is generated by Supabase before the app receives a recovery session. Custom token-hash verification can return the same code. Supabase uses this code for both expired tokens and tokens that cannot be found; it does not prove that the recipient waited too long or previously used the link. The callback uses neutral verification-failure wording. If brand-new emails fail immediately, inspect the project's Auth logs for the `/recover` request and subsequent `/verify` events. Check for intervening recovery requests, invalid token/type combinations, email security prefetching, and SMTP link rewriting. See [Supabase's troubleshooting guide](https://supabase.com/kb/troubleshooting/otp-verification-failures-token-has-expired-or-otp_expired-errors).

The client-only theme provider applies the selected theme before paint without rendering a script element into React. Light/dark/system preferences persist under the existing `theme` storage key, synchronize across tabs, and work in memory when storage is blocked. Browser QA checks those behaviors and fails on the reported script warning. The HTML includes the modern `mobile-web-app-capable` metadata alongside the Apple-specific metadata. React's DevTools download notice is informational.
